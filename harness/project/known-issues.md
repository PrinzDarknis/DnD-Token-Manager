# Known Issues and Tech Debt

Found during the initial harness analysis (2026-10-05). Remove an entry when it is fixed. Severity: **high** (data loss or broken sync), **medium** (bug or leak), **low** (cleanup).

| # | Severity | Area | Issue | Location | Suggested fix |
| --- | --- | --- | --- | --- | --- |
| 3 | medium | leaks | `OwlbearCharacter.registerOnUpdate` and `OwlbearSettings.registerOnUpdate` return `Promise<void>`, not the unsubscribe function, so `CharacterManager`, `CharacterSelect` and `SettingsController` never unsubscribe. The `OwlbearSettings` constructor also registers a listener in every iframe. | `src/owlbear/owlbear-character.ts`, `src/owlbear/owlbear-settings.ts` | Return the `onMetadataChange` unsubscribe and call it in `componentWillUnmount`. |
| 4 | medium | size | No checks against the room metadata limit (< 16 kB total, shared). `METADATA_PUZZLE_LIST` is one growing array; `overwriteAll` and `loadBackup` write many keys at once. | `owlbear-puzzle.ts`, `owlbear-character.ts`, `owlbear-settings.ts` | Size check before writing (`jsonSize`) with a user notification; split the puzzle list per key. |
| 5 | medium | security | Broadcast payloads are not validated: the sound channel only checks `typeof file == "string"` before building a URL, and puzzle payloads are cast with `as`. | `owlbear-settings.ts` (`setupMessageListener`), `owlbear-puzzle.ts` | Check sounds against the allowlist in `sound-board.constant.ts`; add type guards for puzzle payloads. |
| 6 | medium | security | Backup import (`readFile` service → `loadBackup`) writes unvalidated JSON straight to room metadata. | `src/components/ui/import-export/`, `owlbear-settings.ts` | Validate the backup schema (and each character via `Character.restore`) before writing. |
| 7 | medium | correctness | `debounce` returns `void`, so `await Owlbear.character.save()` resolves before the write happens. | `src/utils/debounce.service.ts`, `OwlbearCharacter.save` | Use the promise-returning debounce from `harness/templates/utils/debounce.service.ts`. |
| 8 | low | migration | The 0.1.0 migration runs on every ready in every iframe/client, and cleanup of the legacy `<ns>/characters` key is commented out (`// TODO fix`). | `src/owlbear/version/0.1.0/` | Make it GM-only, finish the cleanup after a successful write, and store a data version. |
| 9 | low | logging | `Logger` imports the `Owlbear` singleton (circular import), and `trace`/`debug` pass `args` as one nested array instead of spreading it. | `src/utils/logging/logger.ts` | Inject the remote sink, spread `...args`. |
| 10 | low | dead code | `src/components/character/character-selector/` duplicates `character-select/` and has no barrel. | components | Delete after confirming it is unused. |
| 11 | low | React | `key={Math.random()}` forces re-mounts; uncontrolled inputs are patched via refs in `componentDidUpdate`. | `character-select`, `character.component.tsx` | Use stable keys; use controlled inputs with a draft when refactoring. |
| 12 | low | trust | GM-only actions are only hidden in the UI; any client can write the metadata. | project-wide | Accept (Owlbear limitation). Keep backups and validate on read. |
| 13 | low | docs | `README.md` is still the Vite template. | `README.md` | Write a user-facing README (install URL, features). |
| 14 | medium | audio | Sounds are played with `new Audio()` in the background iframe after a broadcast (no user gesture there), but the manifests declare no `autoplay` permission, so browsers may block playback. **Unverified**: the user should check in Owlbear whether sounds reliably play for other players. | `src/owlbear/owlbear-settings.ts` (`setupMessageListener`), `public/manifest*.json` | Add `{ "name": "autoplay", "reason": "Play sound board effects for all players" }` to `permissions` in both manifests. |
| 15 | low | sync | Token updates write `item.metadata[...]` through `updateItems`. Per the SDK source, the **whole `metadata` object** of the item is sent, so a concurrent change by another extension (e.g. the stat-bubble extension) or client to a different key on the same token can be overwritten. | `OwlbearCharacter.updateToken` / `updateTokenAll` (`src/owlbear/owlbear-character.ts`) | Keep the read-modify-write window short: pass ids (fresh read) instead of stale item arrays, skip the update when nothing changed (already done via `charUpdateBubbles`). See `harness/owlbear/apis/scene.md`. |
| 16 | medium | storage | Several `localStorage` accesses are not wrapped in try/catch: `PersonalSettingsController.save` (setItem), `OwlbearSettings.saveBackupList` (setItem) and `loadBackups` (getItem outside the try). In private windows or with cookies disabled, storage access throws, so saving personal settings and creating or loading backups fails. Owlbear's verification guidelines require the extension to work there. Backups can also hit the storage quota. | `src/model/settings/personal-settings-controller.ts`, `src/owlbear/owlbear-settings.ts` | Wrap all storage access (and handle quota errors) with an in-memory fallback, and show a notification that backups are unavailable. See `harness/core/05-security.md`. |
